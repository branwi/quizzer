What this app is: one FastAPI server serves a plain HTML/CSS/JavaScript website and a JSON API. SQLAlchemy reads and writes SQLite. Pydantic validates data. There is no Flask server, quiz/attempt engine, background worker, or migration framework in the current source.

Dependency resolution for a protected student operation

    CurrentUser → get_current_user(request, db, settings, bearer)

FastAPI also applies the enclosing API router’s get_current_user dependency. Its normal per-request dependency cache reuses the same provider result where applicable; declaring the requirement in more than one place does not normally repeat the whole lookup. Services remain ordinary functions: calling a service directly does not automatically execute route dependencies.

Transactions: staged changes become durable at commit

A session tracks ORM objects and SQL work. add() stages an object; flush can send pending changes to SQLite; commit completes the transaction. refresh() loads current row values after a write. The request dependency closes the session and rolls back unfinished work. Closing a session is not an implicit successful commit. The code groups normal bulk assignment/import writes into one commit.

CHAPTER 03

Database and data shapes

The join table turns a shared question bank into different current lists for different students. It stores references, so assignment is cheap and editing a question changes every list that references it.

profiles

One row per selected name/grade profile

  • id · primary key
  • first_name
  • grade · string label
  • role · teacher/student

Unique stored (first_name, grade)
id is not reused after deletion

assigned_problems

Many links per student and question

  • student_id → profiles.id
  • question_id → problems.id

Composite primary key: both IDs
question deletion cascades to links

problems

One shared bank question

  • id · primary key
  • type / text / topic
  • choices · nullable JSON
  • correct_answer · JSON
  • explanation · nullable text

Cardinality: one profile can have many links; one question can have many links. Together that is many-to-many. The student role is checked in Python because a foreign key only proves that a profile exists. No relationship() navigation attributes are declared; assignment reads explicitly join tables.

What exists only temporarily?

The response a student types, the current correctness feedback, page counters, search query, and teacher’s unsaved selection live in frontend JavaScript memory. They are not database columns. A login token is returned to the client and placed in a cookie; there is no token/session table. A saved assignment persists until it is replaced or removed, whether or not a student has checked the answer.

Schema creation is not migration

create_all() creates missing current tables. It does not rename old tables, add missing columns to an existing table, copy old accounts, or transform old quizzes into links. Database backups and the older app directory are local history, not an alternative active schema selected automatically. The configured DATABASE_URL determines which database the current engine actually opens.

Create and edit a bank question

Changes problems rows; assigned students see edits to the same ID.

  1. Send a teacher request
    The teacher editor sends POST /api/questions, or PUT /api/questions/<id> for a full replacement. The body includes type, text, topic, format-specific key, and optional explanation. routers/questions.py · create

Adds the Cartesian product of selected IDs while retaining old links.

  1. Submit two nonempty ID lists

async def service_error(_request: Request, exc: ServiceError)

Async exception handler for ServiceError instances raised by services. It maps the exact class ResourceNotFound to HTTP 404 and InvalidInput to HTTP 422, then returns {"detail": str(exc)} as JSONResponse. _request is supplied by FastAPI and unused.

This separates workflow errors from HTTP mechanics. The lookup uses [type(exc)], so adding a new subclass or raising the base ServiceError without extending the map would cause a KeyError rather than a handled workflow response. There is currently no Conflict exception class or 409 mapping, despite older wording in ARCHITECTURE.md’s file table.

async def validation_error(_request: Request, exc: RequestValidationError)

Handles FastAPI RequestValidationError, which covers invalid request bodies, query fields, and path values. It iterates exc.errors() and keeps only type, loc, and msg for each entry, returning a detail array with HTTP 422.

It intentionally drops raw input and context fields so submitted data is not echoed in validation responses. The browser’s request helper reads the final location component and message for display. This handler is distinct from the simpler service InvalidInput handler; malformed schema input and invalid database-dependent input can both be 422 with different detail shapes.

CHAPTER 09

Glossary & reading order

Backend
The Python process that validates requests, checks access, queries/writes storage, and serves responses. Your browser’s JavaScript calls it over HTTP.
API endpoint / operation
A specific method-and-path combination mapped to a function, such as POST /api/questions. GET and PUT on the same path are different operations.
Router
A collection of endpoint registrations with shared prefix, tags, and dependencies. It becomes active only after inclusion in the app.
Service
An ordinary Python module/function implementing workflow rules. It can be called by a router, CLI, or test without an internal HTTP request.
Schema
In schemas.py, a Pydantic input/output contract. In database discussions, “schema” instead means the table/column/constraint structure; these are related but distinct meanings.
ORM
Object-relational mapping: SQLAlchemy connects Python classes/instances to tables/rows. It still executes SQL against SQLite.
Engine
SQLAlchemy’s connection/pooling infrastructure configured for a database URL. It is not a request-specific session or all the database’s contents.
Session
A caller/request-scoped unit of SQLAlchemy work that manages loaded objects and transactions. Services commit; get_db closes it.
Primary key
Column(s) uniquely identifying a row. Profiles/questions have integer IDs; links use both IDs as one composite primary key.
Foreign key
A constraint requiring a reference to an existing row. It does not establish role, identity, ownership, or authorization.
Cascade
A database action propagated through a foreign key. Deleting a problem deletes the links whose question_id references it.
Dependency injection
FastAPI calls provider functions declared via Depends/Annotated and passes their results into handlers or other dependencies.
Validation vs authorization
Validation checks that an input has an allowed shape/value; authorization checks whether the current user may perform the operation. Pydantic does the first, role dependencies the second.
Authentication
Here, token validation plus loading the selected profile. Because initial login accepts an unverified name/grade, this does not establish real-world identity ownership.
JWT / HS256
A compact token of encoded claims plus a keyed signature. HS256 is the chosen signing algorithm. The payload is readable; signing is not encryption.
Cookie / bearer token
Two ways the client transports the same token. Browsers attach a matching cookie; clients can send Authorization: Bearer <token>. This backend prefers a nonempty cookie.
HttpOnly / Secure / SameSite
Cookie flags: HttpOnly prevents JavaScript reading it; Secure restricts transport to HTTPS when enabled; SameSite=Lax restricts some cross-site cookie sending. None replaces server-side role checks.
Serialization
Converting Python values/objects into the response’s JSON shape. A response_model validates/selects the exposed fields.
Discriminated union
One input type chosen among several by a marker field. QuestionCreate looks at type to select MCQCreate, TrueFalseCreate, or ShortAnswerCreate.
Idempotent
Repeating an operation has the same saved effect as doing it once, for the same starting conditions. Sequential repeated additive assignments skip existing links; repeated unassignment can delete zero rows and succeed.
Atomic batch / transaction
A group of database changes committed together. Input/network collection happens before normal batch mutations, and a failed uncommitted transaction is rolled back when closed. This does not imply concurrency locking across the full workflow.
Pagination
Querying a bounded slice using ORDER BY, LIMIT, and OFFSET, with a total count to compute page navigation.
Generator / yield
A function can pause at yield and resume later. get_db lends a session through yield; fetch_batches yields downloaded batches; lifespan uses an async generator for startup/shutdown.
Callback
A function supplied for another component to invoke. SQLAlchemy calls configure_sqlite when a connection opens; import_online calls its optional progress function after a batch.
